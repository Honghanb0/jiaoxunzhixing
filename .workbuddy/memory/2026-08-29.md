## 多模型统一接入层（DeepSeek / Kimi / GLM）

为 security-agent 新增统一大模型接入层，收敛三家的端点、请求格式与鉴权差异。

### 新增/改造文件
- `internal/ai/provider.go` — `Provider` 接口、统一 `ChatRequest/ChatResponse/Usage/StreamChunk`、`ProviderResult`、供应商元数据与默认端点/模型表。
- `internal/ai/openai_compat.go` — OpenAI 兼容通用传输层：指数退避重试（可重试码 408/429/5xx，401 不重试）、SSE 流式解析、ctx 取消即时退出、连接池复用。
- `internal/ai/providers.go` — 三家适配器工厂。GLM 的 Key 形如 `id.secret`，用 `golang-jwt/jwt/v5` 签发（header 带 `sign_type: SIGN`，claims 含 `api_key`/`exp(毫秒)`/`timestamp`），缓存至到期前 30s；不含 `.` 的新版直传 Key 直接用 Bearer。
- `internal/ai/manager.go` — 路由中心，三种策略 `single`/`fallback`/`parallel`，运行时 `SetDefault` 切换，并行调用带 `recover` 防单家 panic 拖垮整体。
- `internal/ai/module.go` — 业务门面，`Available()` 让无 Key 时直接走本地模板报告，不空耗超时。
- `internal/api/ai_handler.go` — `GET /api/ai/providers`、`POST /api/ai/chat`、`POST /api/ai/chat/stream`(SSE)、`POST /api/ai/compare`、`POST /api/ai/providers/:name/test`、`PUT /api/admin/ai/default`(管理员)。
- `internal/config/config.go` — 新增 `ai.providers` 多模型配置 + `normalizeAIConfig()` 兼容旧版扁平 `ai.provider/api_key/model/base_url`。
- `cmd/server/main.go` — 新增 `-config` 参数；AI Manager 与 Engine 改为进程内单例，修复调度器 `engine` 传 nil 的潜在崩溃。
- `web/index.html` — 新增「AI 模型」页签（模型列表/连通测试/设为默认/对话/并行对比）。

## 登录 "Failed to fetch" 故障修复

### 根因（两个）
1. **前端硬编码 API 基址**：`const API_BASE = 'http://localhost:8080/api'`。页面只要不是从 `http://localhost:8080` 打开（如 `127.0.0.1:8080`、IDE 预览面板、其他端口），请求即变为跨域/混合内容，浏览器在网络层拦截，`fetch()` 抛 `TypeError: Failed to fetch`，根本拿不到响应。
2. **CORS 未放行 Authorization**：`Access-Control-Allow-Headers` 只有 `Content-Type`，导致登录后所有带 Bearer Token 的请求在预检阶段被拒。

### 修复
- `web/index.html`：`API_BASE` 改为同源动态解析（`location.origin + '/api'`，file:// 时回退 localhost）。
- `internal/api/server.go`：`corsMiddleware` 增加 `Authorization, X-Requested-With, Accept`、`Expose-Headers`、`Max-Age`，按 Origin 回显并带 `Vary`。
- `web/index.html`：新增 `APIError` + `apiRequest()` 统一请求层（AbortController 超时、网络/超时/HTTP/解析分类型、`httpErrorText()` 状态码中文映射、`diagnoseNetworkFailure()` 区分「服务没起」与「被浏览器拦截」）、`showToast()` 全局提示、登录按钮 loading 态。
- 关键行为修正：`validateToken()` 从返回 boolean 改为 `ok|unauthorized|unreachable`，**服务不可达时不再清空登录态**（此前会把用户强制登出）。

### 二次修复：候选地址自动回退（用户仍报"无法连接到服务器"）
只认同源并**不够**。若页面由 IDE 预览面板之类的第三方端口托管（实测 `127.0.0.1:58815` 静态快照），
同源地址上根本没有 `/api`，一样连不上。改为候选列表 + 自动回退：

- `buildAPIHostCandidates()`：候选顺序 = 上次成功地址(localStorage `api_host`) → `location.origin` → `http://localhost:8080` → `http://127.0.0.1:8080`。
- `apiRequest()` 在网络层失败时轮转候选重试；**HTTP 401/403/5xx 不换地址**（说明地址是对的）。
- 连通后 `rememberAPIHost()` 持久化；启动时 `initAPIHost()` 先主动探测（3s 超时）定位可用地址。
- `describeAllHostsDown()`：若探测到某地址有服务但页面访问不了，提示"跨域被拦截，请直接打开 xxx"；全不通则列出已尝试的全部地址。
- 登录页底部新增「服务地址: xxx」实时指示，便于自查。

### 验证
`tools/verify_login.js` 在 Node 中加载页面**真实 `<script>`**（DOM stub + 真 fetch）调用真实 `apiRequest`，
15 项全 PASS，覆盖 5 个场景：后端自托管 / 预览面板跨端口自动回退 / 全地址不可达的中文提示 /
死来源但后端正常时自动救回 / 状态码中文映射。
测试钩子 `setAPIHosts()` 用于构造"所有候选都不可达"。
注意：脚本里 `API_BASE`/`API_HOST` 必须用 getter 返回，否则拿到的是快照值。

## 登录表单"账号被清空"故障修复（第三轮）

现象：输入账号后切到密码框，账号值消失，提交时账号为空。

### 根因
`web/index.html` 末尾有一个**在脚本加载时无条件注册**的 10 秒轮询：
```js
setInterval(async () => { await loadDashboard(); ... }, 10000);
```
未登录时这些请求必然 401 → `fetchAPI` 里 `if (err.status === 401) logout()` →
`logout()` 中 `document.getElementById('loginUsername').value = ''`。
即**每 10 秒抹掉一次用户正在输入的内容**，与"输完账号切到密码框"的几秒间隔正好重叠。
次要触发点：`DOMContentLoaded` 里 `validateToken()` 返回 unauthorized 也会调 `logout()`。

### 修复（三层防护）
1. **轮询门禁**：改为 `startAutoRefresh()/stopAutoRefresh()`，只在 `showMainApp()`（已登录）时启动；
   tick 内二次校验（无 token 或 mainApp 隐藏即自停）；`logout()` 中调用 `stopAutoRefresh()`。
   已确认全文件无顶层无条件 `setInterval`（只剩扫描进度 `scanProgressTimer`，用户触发且有 clear）。
2. **`logout(options)` 不再无差别清表单**：`{userInitiated:true}` 才清（且只清密码、保留账号）；
   程序性登出（401/过期）完全不碰输入框，末尾只调 `restoreLoginForm()`。
   退出按钮改为 `onclick="logout({userInitiated: true})"`。
3. **表单状态管理**：`loginFormState{username,password}` + `oninput/onfocus/onblur` 三事件同步；
   `readLoginForm()` 读取时 DOM 优先、state 兜底；DOM 被外部清空时 focus/blur 自动写回；
   账号持久化到 localStorage(`login_username_remember`)，`prefillLoginUsername()` 新页面带出。
   输入框补 `autocomplete="username"/"current-password"`。

### 验证
`tools/verify_login.js` 新增场景六（表单状态保持，11 项）与场景七（轮询门禁，4 项），共 26 项全 PASS。
脚手架要点：`runPage()` 需按 id 持久化 element（否则 value 不保留）、支持 `sharedStore` 共享 localStorage。

## 项目约定 / 踩坑
- 用 `nohup ./security-agent.exe > server.log 2>&1 &` 启动服务时，**不要把它接在 `&&` 命令链后面**——整条链会被后台化，工具调用结束时被一并杀死。单独一条命令启动，再在下一条命令里检查。
- 默认管理员：admin / Admin@123；`AUTH_DEFAULT_ADMIN_PASSWORD` 可覆盖，`RESET_ADMIN_PASSWORD=1` 强制重置。
