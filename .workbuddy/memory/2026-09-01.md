### 6. Bug 修复：404 / 「查看」无反应 / 工单调试日志（Request C）
- 根因：`internal/agent/task.go` 的 `taskRepo.Get` 原 Cypher 末尾 `... RETURN t, collect(s) AS steps ORDER BY s.created_at` —— `ORDER BY` 引用了 OPTIONAL MATCH 聚合前的字段 `s.created_at`，当任务无执行步骤（`s` 为 null）或 Neo4j 版本校验该 ORDER BY 不在 RETURN 列表时静默报错；且原实现**未调用 `res.Err()`**，导致 `res.Next()` 返回 false→上层误判 `task not found`→ `GET /api/agent/tasks/:id` 返回 404。内存中运行中的任务走 `Manager.Get` 内存快照→200，已落库（进程重启后）的任务走 repo.Get→404，故旧任务「查看」按钮无反应。
- 修复：
  - `task.go` `taskRepo.Get`：去掉 `ORDER BY s.created_at`，改为 Go 侧 `sort.SliceStable` 按步骤 `CreatedAt` 排序；新增 `res.Err()` 检查 + 节点类型断言失败日志；全程加 `[Agent][taskRepo.Get]` 日志（查询开始/失败/成功 steps=N/遍历告警/无记录）。新增 `sort`、`log` import。
  - `manager.go` `Get`：加 `[Agent][Manager.Get]` 日志（命中内存快照 / 回退 Neo4j）与 `log` import。
  - `agent_handler.go` `GetTask`：404 前加 `[API][Agent] GetTask 未找到任务 id=.. err=..`，并记录真实底层错误；加 `log` import。
  - `tools_action.go` `create_ticket`：调用前打 `[Agent][create_ticket] 调用开始 args=..`、成功打 `创建成功 ticket_id=..`、失败打 `创建失败 .. err=..`；加 `log` import。
  - `web/index.html`：`doRequest` 加请求(方法/URL/auth/bodyLen)与响应(status/ok/contentType)日志；`fetchAPI` 加 method/url/params 与错误 kind/status 日志；新增 `logAgent()` 前缀助手；`pollAgentTask` 收到 null（404/网络）时**停止轮询并 showToast 一次**（修复按钮“无反应”假象）+ 步骤日志；`runAgentTask`/`loadAgentTasks` 加目标与返回计数日志。前端 JS 经 `node vm.Script` 校验通过。
- 验证（重启 8080 清空内存，全部走 repo.Get）：
  - 列 13 个任务，逐一对 `GET /agent/tasks/:id`：全部 200（含此前 404 的 f87cc61d/c44a5b6d/91e4dbb4/37b62304/5aacad44）。
  - 实跑一次智能体巡检（靶场 8099）：扫描 16 页/163 漏洞（高27/中95/低41），调用 create_ticket 创建工单（id 48d59013，risk=high P1），日志完整捕获 args→成功；测试工单已软清理 status=excluded。
- 结论：三项故障（查看无反应、404、工单不可见）均修复，且相关路径已具备请求参数/响应状态/错误堆栈级调试日志。
